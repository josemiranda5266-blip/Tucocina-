# Tucocina — Auditoría técnica 2026-09-09

## Objetivo

Dejar el MVP preparado para crecer con **mínimo costo operativo**, buena seguridad y consultas de Firestore eficientes. La prioridad es evitar descargas completas de colecciones, eliminar bypasses de autorización y mantener la IA fuera del camino crítico.

## Cambios implementados

### Seguridad
- `TUC-SEC-001` — Eliminado el email hardcodeado como administrador en backend. El servidor usa exclusivamente el custom claim de Firebase `admin == true`.
- `TUC-SEC-002` — Firebase Admin falla cerrado en producción si faltan `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL` o `FIREBASE_PRIVATE_KEY`.
- `TUC-SEC-003` — Firestore usa custom claim para administración y endurece escrituras de usuarios, favoritos y reportes mediante listas de campos permitidos e invariantes.
- `TUC-SEC-004` — Allowlist de URLs externas endurecido: HTTPS obligatorio, hosts exactos de YouTube/Instagram/TikTok y bloqueo de rangos locales/privados conocidos.
- `TUC-SEC-005` — Eliminado también del frontend el email hardcodeado. `AuthContext` obtiene el rol administrativo desde `getIdTokenResult().claims.admin`; el cliente nunca puede elevarse a ADMIN por email.
- `TUC-SEC-006` — El frontend ya no confía ciegamente en `embedUrl` ni `originalUrl`: valida protocolo, host y patrón de ruta antes de crear iframes o enlaces externos.
- El conector de YouTube genera un endpoint oEmbed fijo de YouTube y aplica timeout corto; no utiliza la URL arbitraria del usuario como destino de la petición de enriquecimiento.
- TikTok no acepta una URL sin ID de video válido.
- El detalle público de un video solo devuelve documentos `PUBLISHED`.
- CORS exige `ALLOWED_ORIGINS` explícito en producción.
- Se añadieron headers de seguridad básicos y HSTS en producción.
- Rate limiting ya no confía directamente en `X-Forwarded-For`; utiliza `req.ip` y un almacenamiento en memoria con limpieza periódica.

### Costos, rendimiento y contratos API
- `TUC-DATA-001` — Catálogo público migrado de `page + slice()` a paginación por cursor de Firestore.
- `TUC-API-005` — Frontend migrado para consumir `cursor`/`nextCursor`; búsqueda y catálogo administrativo ya no envían `page` al backend.
- El catálogo solicita solo `limit + 1` documentos para determinar `hasMore`.
- `total` se obtiene mediante `count()` cuando no hay búsqueda textual, evitando descargar toda la colección.
- `TUC-DATA-002` — Favoritos paginados por cursor y solo se consultan videos publicados correspondientes a la página solicitada.
- `TUC-PERF-001` — Eliminada la carga completa de favoritos.
- `TUC-API-001` — Reportes administrativos paginados y filtrables por estado.
- `TUC-API-002` — Métricas administrativas migradas a consultas de agregación `count()` en lugar de descargar videos, reportes y usuarios completos.
- `TUC-API-006` — Corregidos contratos frontend/backend de favoritos y reportes: el frontend ahora consume `{ items, hasMore, nextCursor }`.
- `TUC-API-007` — Unificado el estado de reportes en `REJECTED`.
- Conteo de vistas cambiado a incremento atómico para evitar pérdida de actualizaciones concurrentes.
- Eliminado el ordenamiento/paginación en memoria de los listados administrativos.
- Se añadió manejo de errores API más consistente y `encodeURIComponent` para IDs enviados en rutas.
- Se añadieron estados de error visibles en búsqueda, catálogo administrativo, favoritos y reportes.
- Imágenes de miniaturas administrativas usan `loading="lazy"`.
- Se eliminó `@google/genai` del runtime porque la IA no forma parte del camino crítico del MVP.
- Dependencias de build movidas a `devDependencies` para reducir la superficie de producción.

### Frontend, SEO y accesibilidad
- `TUC-FE-001` — Eliminado el branding histórico `CO-Cocina` del HTML raíz. `title`, description, Open Graph, Twitter Card y locale ahora describen Tucocina.
- `TUC-BUILD-001` — Eliminado el plugin de medios específico de AI Studio y el placeholder `public/assets/aistudio`; el MVP ya no depende de esa infraestructura de prototipo.
- `TUC-A11Y-001` — Header reforzado con semántica de navegación, botón de marca, labels para controles de icono, `aria-expanded` en menú móvil y `aria-hidden` en iconos decorativos.
- La revisión visual/funcional de las demás páginas, rutas y formularios continúa pendiente de validación con build y ejecución real.

## Decisiones de costo

1. No se incorpora un motor de búsqueda externo todavía.
2. La búsqueda textual actual está acotada a una ventana máxima de 500 documentos para evitar lecturas sin límite. Es una solución MVP y será sustituida por búsqueda indexada si el catálogo crece.
3. Firestore sigue siendo el almacenamiento principal y se priorizan índices, límites y cursores.
4. `count()` se usa donde aporta valor. Para datasets realmente grandes se evaluarán contadores materializados para reducir escaneo de índices.
5. No se agrega IA al flujo normal de usuario.
6. Los enriquecimientos externos son best-effort y tienen timeout corto.
7. No se introduce Redis u otra infraestructura solo para rate limiting en esta etapa: para el MVP se prioriza costo mínimo. Si se escala a múltiples instancias, deberá migrarse a un limitador distribuido.
